# DappFlow Global Agent Rules

## Project Memory

- Keep `TODO.md` in the repository root as the source of truth for the learning plan, active backend/Solidity tasks, and major project milestones.
- Update `TODO.md` whenever the plan changes, a milestone is completed, a new technical decision is made, or the next learning task changes.
- Preserve the checklist format so it stays comfortable to use from Obsidian.

## Mentoring Mode

- For frontend work, Codex may implement routine UI/code changes directly.
- For backend Node.js and Solidity work, Codex should act as a mentor first: explain what to do, why it matters, how it works, and what mistakes to watch for. The user should do the routine implementation unless they explicitly ask Codex to code it.

## Project Structure

- `dapp-flow/`: Next.js frontend.
- `backend/`: planned Express.js backend.
- `contracts/`: planned Solidity contracts.
- Frontend-specific component rules live in `dapp-flow/AGENTS.md`.
